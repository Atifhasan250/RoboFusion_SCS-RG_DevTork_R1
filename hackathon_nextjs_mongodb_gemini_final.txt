==================================================
9. DUPLICATE READING HANDLING
==================================================

প্রতিটি Reading Unique হবে:

Unique Compound Index:

{ zoneId: 1, bootId: 1, sequence: 1 }

unique: true

Recommended Processing:

1. Zone authenticate
2. Payload validate
3. MongoDB Session শুরু
4. Transaction-এর ভিতরে Reading insert করার চেষ্টা
5. Insert সফল হলে Risk/State/Incident/Command Process
6. Duplicate Key Error E11000 হলে Transaction abort
7. Existing Reading/Current Command fetch করে duplicate = true Return
8. Duplicate Request-এর জন্য কোনো State Version Increment হবে না

একই Reading Network Retry-এর কারণে আবার এলে:

1. নতুন Reading Document তৈরি করা যাবে না

14. RISK FUSION FORMULA
==================================================

Formula এমন হতে হবে যাতে:

1. Confirmed Fire একা CRITICAL হতে পারে
2. Severe Gas একা CRITICAL হতে পারে
3. Severe Water Leak একা CRITICAL হতে পারে
4. একাধিক Moderate Hazard Fusion হয়ে CRITICAL হতে পারে
5. Occupancy একা Hazard তৈরি না করে
6. Final Score 0-100 থাকে

Recommended Formula:

fire_component = 70 × fire_factor
gas_component = 70 × gas_factor
water_component = 70 × water_factor
occupancy_component = 10 × occupancy_factor

risk_score =
min(
  100,
  fire_component
  + gas_component
  + water_component
  + occupancy_component
)

Where:

1. fire_factor = 0 অথবা 1, Backend Debounce-এর পরে
2. gas_factor = 0.0 থেকে 1.0
3. water_factor = 0.0 থেকে 1.0
4. occupancy_factor = 0 অথবা 1

Classification:

risk_score < 30
= SAFE

30 <= risk_score < 65
= WARNING

risk_score >= 65
= CRITICAL

Formula Explanation:

1. একটি Confirmed Fire দ্রুত Critical হতে পারবে
2. Gas Critical Calibration Point-এ পৌঁছালে Zone Critical হবে
3. Water Critical Calibration Point-এ পৌঁছালে Zone Critical হবে
4. Gas ও Water দুইটি Medium Hazard একসঙ্গে Critical করতে পারবে
5. Occupancy Risk বাড়াবে কিন্তু একা Warning/Critical করবে না
6. Score 100-তে Cap হবে

IMPORTANT:

1. Final Formula Developer এবং Designer একসঙ্গে Final করবে
2. Code, Documentation এবং Video-তে একই Formula থাকবে
3. Formula পরিবর্তন করলে সব জায়গায় Update করতে হবে
4. Risk Component API Response-এ আলাদাভাবে Return করতে হবে

Risk Response Example:

{
  "risk_score": 88.5,
  "components": {
    "fire": 70,
    "gas": 8.5,
    "water": 0,
    "occupancy": 10
  }
}

15. STATE HYSTERESIS AND FLAPPING PREVENTION
==================================================

Zone যেন দ্রুত:

CRITICAL → SAFE → CRITICAL

Flip করে Duplicate Incident Flood না করে।

Recommended State Rules:

ENTER WARNING:
1. Risk >= 30
2. অন্তত 2 consecutive valid readings

ENTER CRITICAL:
1. Risk >= 65
2. অন্তত 2 consecutive valid readings
3. Confirmed Fire Debounce সম্পন্ন হলে Immediate Critical অনুমোদিত

RECOVER CRITICAL TO WARNING:
1. Risk < 55
2. অন্তত 5 seconds Stable

RECOVER WARNING TO SAFE:
1. Risk < 25
2. অন্তত 5 seconds Stable

এই Difference-কে Hysteresis বলা হবে।

State Transition Service এক জায়গায় থাকবে।

Frontend বা API Router-এর ভিতরে State Logic লেখা যাবে না।

18. PRIORITY RANKING ENGINE

Ranking Factors:

1. Risk Score
2. Occupancy
3. কত সময় ধরে Critical
4. Deterministic Tie-breaker

Recommended Formula:

occupancy_bonus =
10 if occupied
else 0

duration_bonus =
min(
  10,
  critical_duration_seconds / 30
)

priority_score =
risk_score
+ occupancy_bonus
+ duration_bonus

Tie-break Order:

1. Higher priority_score
2. Higher risk_score
3. Occupied Zone আগে
4. Earlier critical_since আগে
5. Zone Code Alphabetical, final deterministic fallback

Ranking প্রতি State Change এবং নির্দিষ্ট Interval-এ Recalculate হবে।

Ranking API-তে Return করবে:

1. Rank
2. Zone
3. Risk Score
4. Priority Score
5. Occupancy
6. Critical Duration
7. Primary Hazard
8. Ranking Reason

Ranking Reason Hardcoded Static Text হবে না।

1. PIR true, Camera true
   → Occupied

2. PIR false, Camera true
   → Occupied

3. PIR true, Camera false
   → Occupied

   → Empty

   → Camera Result ব্যবহার

2. camera_occupied
3. combined_occupied
4. occupancy_source
5. disagreement flag
